# Полнота сбора и здоровье хранения

[English](COLLECTION_HEALTH.md)

В 0.11.2 отдельно учитываются штатные исходы инструментов, квитанции помощников и приёмка задач человеком. Завершение команды не доказывает успешную проверку. Квитанция не переписывает старые неизвестные события.

Включение квитанций для настоящей проверки:

```sh
python scripts/workflow_check.py check --output work/check.json --pulse-state /absolute/private/pulse-state --pulse-provider codex
python collector.py journal --action checks
python collector.py journal --action health
python collector.py journal --action backup --file /absolute/private/backups/journal.sqlite
```

Хранятся только фиксированная операция, публичная версия, хеш ID запуска, время, статус, хеш исходников и разрешённые статусы проверок. Клиент указан передающей стороной. Повторы не суммируются, противоречивые завершения остаются неизвестными. Видны пропуски начала, незавершённые/давние запуски и противоречия. Ошибка телеметрии не меняет результат проверки; `receiptSaved` сообщает, удалось ли сохранить запись. Срок квитанций 30 дней, предел 5 000 записей. Нативные hooks и модель не изменяются.

MCP `pulse_collection_health` и `pulse_check_receipts` доступны для чтения. `pulse_record_check` и `pulse_backup_journal` требуют явного `--allow-control`. Произвольные команды, модель и восстановление не запускаются. Результат заявляет помощник: он отдельно от штатного подтверждения и приёмки.

Диагностика показывает быструю проверку SQLite, число событий, единый предел анализа и хранения 100 000 событий, срок 30 дней и счётчики удалённых по сроку/пределу событий. Рядом дата начала счётчика: ранее удалённое неизвестно. Быстрая проверка не заменяет полную диагностику; автоматического ремонта нет.

Резервная копия создаётся согласованным SQLite backup, проверяется и сохраняется без перезаписи существующего файла. На POSIX права 0600; на Windows нужен закрытый профиль пользователя. Копируются очищенный журнал и хешированные ID, без Secrets.json, ключей и нативных баз. Отпечаток связывает копию с текущей локальной идентичностью сборщика. Восстановление не выполняется; при последующем ручном восстановлении сохраните исходную локальную идентичность, чтобы новые ID были совместимы. Ручные копии не удаляются автоматически по сроку активного журнала.

Сравнение задач теперь отдельно проверяет полноту для вызовов на принятый результат, суммы интервалов задач на результат, явно переданных запросов модели и токенов. Учитываются выбранные неудачные попытки, сохраняются ограничения по группам и качеству. Отсутствующие токены не блокируют доступные операционные показатели. Интервалы включают ожидания и могут пересекаться: сумма не равна активному рабочему времени. Причинная экономия и экономия подписки не выводятся.

**100% известных квитанций — только среди записанных запусков помощника.** Полный охват агента остаётся неизвестным: у некоторых инструментов нет hook-событий, формат результата зависит от инструмента. [Штатный контракт](https://learn.chatgpt.com/docs/hooks) проверен 2026-10-09. Неизвестные результаты не превращаются в успехи.


Для начала, завершения и повтора используйте один исходный эфемерный runId. Возвращается HMAC, а не исходный nonce; не передавайте его как новый ID производителя.
