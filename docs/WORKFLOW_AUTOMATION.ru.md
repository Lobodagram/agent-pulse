# Дневная сводка и общий запуск нативных проверок

[English](WORKFLOW_AUTOMATION.md)

Помощники объединяют существующие операции. Они не запускают агентов, не читают приватные базы клиентов, не меняют подписки и не отправляют телеметрию наружу.

## Сводка за местный день одной командой

```sh
python collector.py journal --action daily --date 2026-10-12 --utc-offset-minutes 120 --provider glm --format markdown --language ru --file work/daily-glm.md
```

Read-only MCP `pulse_daily_review` принимает `date`, необязательные `utcOffsetMinutes`, `provider` и `language`. Без языка возвращается JSON, с `en` или `ru` — Markdown. Без клиента MCP включает наблюдаемых в этот день клиентов и клиентов из реестра Пульса. В CLI сохранён прежний клиент по умолчанию (`codex`); для GLM укажите `--provider glm`.

Счётчики вычисляются из всей сохранённой выборки дня, независимо от усечения диагностических групп. Отчёт содержит известные парные результаты, неизвестные исходы, до пяти кандидатов на улучшение на клиента с ограниченными примерами, категории ошибок и следующие шаги, охват распознавания команд/скиллов, квитанции помощников и оценки задач, записанные в этот день. Дата записи оценки не устанавливает дату выполнения задачи.

Квоты читаются только из собственной `metrics.sqlite` Пульса, без запросов провайдерам или чтения хранилищ клиентов. Отсутствующая база не создаётся. Старые и кешированные наблюдения исключены; разные пулы лимита не смешиваются. Разница в процентных пунктах показывается только между пригодными наблюдениями одного известного окна сброса, без смены аккаунта, повышения остатка или усечения выборки. Дневной расход пятичасового лимита при сбросах остаётся неизвестным. Предел — 2000 снимков на клиента; при усечении крайние точки относятся к ограниченной выборке и не доказывают полный дневной расход.

Токены за UTC-день остаются отдельным полем с источником. При ненулевом смещении их день отличается от местного дня операций. Скидки кэша, тарифицируемые токены, расход одного вызова и причинная экономия подписки не выводятся.

## Короткая сводка для экономии

```sh
python scripts/economy_review.py --date 2026-10-14 --utc-offset-minutes 180 --output work/economy-20261014
```

Одна команда собирает GLM и Codex через установленный `pulse-collector` и печатает короткий отчёт вместо полных JSON. Полная очищенная выборка сохраняется локально; каталог результата должен быть новым. Это отдельный скрипт репозитория, интерфейс установленного приложения не меняется. На другой платформе передайте `--collector /absolute/path/to/pulse-collector`. Сводка не вызывает модель, не запускает фонового наблюдателя и не меняет настройки клиентов.

Приоритеты: известные ошибки перед повтором, неизвестные команды перед автоматизацией, проверка гипотез повторов, реальные оценки задач. Повторы могут пересекаться; их количество не равно лишним действиям или потерянным токенам. Расход лимитов сохраняет ограничения дневной сводки, сообщённые UTC-токены показаны отдельно.

Если уже есть реальные оценки сопоставимых задач, добавьте `--label <task-label> --before <baseline-variant> --after <improved-variant>`. Скрипт использует существующие ворота `compare-tasks`: минимум три задачи на вариант, известные модели и выборки, сопоставимые группы и сохранённое качество. Каждый ресурс оценивается отдельно; отсутствие токенов не блокирует пригодное сравнение числа вызовов. Автоматическая приёмка задач и причинная экономия подписки не выводятся.

## Нативные fixture-проверки одним запуском

На macOS передайте подготовленную сборку Пульса, предпочтительно временный кандидат:

```sh
python scripts/native_qa.py --binary '/absolute/candidate/Agent Pulse.app/Contents/MacOS/AgentPulse' --output work/native-qa
python scripts/native_qa.py --binary '/absolute/candidate/Agent Pulse.app/Contents/MacOS/AgentPulse' --output work/native-qa-next --previous work/native-qa/receipt.json
```

Папка результата должна быть новой. Запускаются существующие проверки виджета, истории моделей, графиков и эффективности. После каждого набора сохраняется прогресс. Результат — `receipt.json`, логи и `gallery.html` со ссылками на полноразмерные снимки. `--suites models charts` выбирает часть проверок. На неподдерживаемой ОС помощник явно откажется запускаться.

`--previous` предназначен только для доверенной локальной квитанции. Повторное использование требует совпадения байтов сборки, demo-данных, помощника, скрипта конкретного набора и окружения, а также хэшей каждого снимка и fixture-квитанции. Отсутствующие или изменённые материалы, ошибки и изменения входов отменяют reuse. Изменение сборки/fixture во время запуска аннулирует результаты. Ошибка одного набора не скрывает исходы остальных. Проверки работают с временными копиями и своими идентификаторами; установленное приложение, его настройки и состояние аккаунтов не меняются.

Автоматические проверки не заменяют визуальную оценку изменённых экранов на полном размере: RU/EN, минимальные размеры, большие/нулевые/отсутствующие значения. Reuse не означает новую приёмку человеком. Source/frozen-проверки остаются отдельными воротами: [сборка](BUILDING.ru.md), [QA](QA.md).

## Ошибки перед автоматизацией

Команда `python scripts/workflow_check.py check --output work/preflight/check.json --test-log work/preflight/tests.log` сохраняет ограниченный приватный лог тестов в том же запуске. При ошибке прочитайте этот файл вместо повторного прогона всех тестов ради traceback. В сводку и handoff попадают только статус и размер лога, без его содержимого и пути. Лог хранит последние 30000 байт UTF-8 с отметкой усечения; ранние ошибки могут быть пропущены. Оставляйте его локальным. Обязательные проверки не кешируются и не пропускаются.

Для сообщённых категорий syntax/reference/type/module/permission/timeout/connection сводка выдаёт фиксированные следующие шаги. Неизвестная категория остаётся неизвестной; её нужно получить при следующей естественной ошибке. Не восстанавливайте прошлые сообщения, не устанавливайте пакеты без разрешения и не повторяйте вслепую действия, которые могли уже изменить состояние.

Для сравнения «до/после» нужны реальные оценки задач, сопоставимый объём и измеренный ресурс. См. [цикл улучшений](IMPROVEMENT_LOOP.ru.md).
