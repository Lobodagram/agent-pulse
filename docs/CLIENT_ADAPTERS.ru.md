# Адаптеры клиентов — проверено 2026-10-06

[English](CLIENT_ADAPTERS.md). Это предложение, плагины не установлены. См. [текущие интеграции](INTEGRATIONS.md) и [модели](MODELS.ru.md).

Один локальный журнал Agent Pulse и небольшие адаптеры для каждого клиента. Сам клиент управляет моделями, инструментами, сессиями, доступом и оплатой. Плагин упрощает установку/удаление наблюдателя, но не открывает данные, отсутствующие в интерфейсе расширений.

| Клиент | Подтверждённая возможность | Текущее состояние Agent Pulse |
| --- | --- | --- |
| Codex | Хуки/MCP в плагине, штатная статистика аккаунта | Собственные наблюдатели и локальный MCP есть; отдельного опубликованного плагина и подтверждённого API даты продления нет. [Документация](https://developers.openai.com/plugins/build/plugins) |
| ZCode | Плагин с хуками/MCP, агрегаты приложения и Coding Plan | Локальные наблюдатели работают; модели каждого вызова и адаптер оплаченного плана пока не завершены. [Плагины](https://zcode.z.ai/en/docs/plugin), [хуки](https://zcode.z.ai/en/docs/hooks) |
| Claude Code | `PostModelSwitch`, версия 2.1.251+ | Кандидат для истории выбранной модели сессии. Событие не покрывает все подмены модели на один ход; модель сессии и фактическая модель вызова должны различаться. [Документация](https://code.claude.com/docs/en/hooks#postmodelswitch) |
| Kimi Code | Авторизованный локальный `GET /api/v1/oauth/usage` | Кандидат для лимитов OAuth-аккаунта; подтверждены окна/сбросы, дата продления этим контрактом не установлена. Совместимость установленного Kimi Work/Chat не доказана. [API](https://www.kimi.com/code/docs/en/kimi-code-cli/reference/server-api.html) |

## Как внедрять

1. Определить явно выбранный установленный клиент и его поддерживаемую версию, без поиска переписок и извлечения секретов. Отключённые клиенты не опрашиваются.
2. Подготовить конкретный манифест адаптера: события/GET, разрешённые поля, область аккаунта/сессии, частота, ограничения, хранение и удаление. Сохранить пользовательские обработчики и не дублировать одни события плагином и пользовательским хуком.
3. Пройти штатную проверку хуков. Установка плагина не означает доверия. Не прерывать работающий GLM ради активации конфигурации; применять в новой сессии.
4. Передавать только идентификаторы, штатные модели/переключения, числовой расход, окна квот и явно сообщённые даты оплаты. Переписки, рассуждения, аргументы, результаты, cookies и скриншоты исключены. Доступом управляет клиент; отдельно переданный ключ адаптера — только в локальном Secrets.json.
5. Хранить источник/время, хешировать идентификатор аккаунта. Разделять общую историю работ и квоты аккаунта, выбранную и фактическую модель, сброс квоты и продление подписки, штатную и ручную дату. Месячный сброс не доказывает дату оплаты.
6. Проверить реальные начала/завершения, смены модели/аккаунта, ошибки, удаление и повторную доставку. GET с побочным восстановлением сессии не подходит пассивному наблюдателю.

Приоритет: достоверные модельные события известных клиентов, затем локальные квоты Kimi Code и оплаченный план ZCode при наличии поддерживаемых контрактов. Личный дашборд можно просмотреть штатно; извлечение cookies, обход закрытых API и произвольный захват экрана не входят в архитектуру. Это не юридическая гарантия: использовать поддерживаемые интерфейсы с разрешённым доступом и условиями поставщика, без обхода авторизации. Недоступные поля оставлять ручными/неизвестными.

Начать распространение можно с проверенных локальных/GitHub-пакетов. У публичного каталога OpenAI отдельная проверка и ограничения локального MCP. Ради каталога не следует открывать локальную аналитику в интернет.
