# Настройка и управление через агента

С 0.9.5 занятая блокировка настроек возвращает результат инструмента с `isError: true` и фиксированным JSON `{"error":"config_busy","retryable":true}`. Повторите действие после завершения другой записи; автоматического цикла агента нет. Запрещённые инструменты и неверные параметры остаются ошибками протокола. Пути, входные данные и текст исключения не выдаются. Mac уже перечитывает визуальные настройки каждые пять секунд без перезапуска и ручного обновления.

Пришлите агенту ссылку на репозиторий и попросите: «Прочитай docs/AGENT_SETUP.ru.md, проверь мою установку Agent Pulse, настрой нужных клиентов без раскрытия ключей и объясни полноту сбора». Это локальные инструменты, а не постоянная панель внутри чата. Сам Agent Pulse модели не вызывает; работа агента по вашему запросу расходует его обычную подписку.

## Сначала определить ОС и способ установки

Проверьте ОС, её версию и архитектуру процессора штатными средствами. Затем выберите **готовый пакет** или **исходники**. Не ставьте сборочные зависимости для запуска готового приложения и не обновляйте системный Python/ОС/клиенты без необходимости и разрешения владельца. При неподдерживаемой среде остановите установку и объясните ограничение.

| Среда | Готовый пакет | Зависимости пользователя и границы |
| --- | --- | --- |
| macOS 14+, Apple Silicon ARM64 | `agent-pulse-macos-arm64.zip` | Python и runtime внутри `.app`; для готового пакета не нужны Python, Xcode или PyInstaller. Поместите приложение в постоянное место, например `/Applications`, до установки наблюдателей. |
| macOS 14+, Intel x64 | `agent-pulse-macos-x64.zip` | Те же правила; не подменяйте архитектуру сборки. Подпись ad-hoc, нотариальная проверка Apple отсутствует; не обходите Gatekeeper автоматически. |
| Windows 10/11 x64 | `agent-pulse-windows-x64.zip` | Python/Tk/runtime упакованы. Распакуйте **всю** папку в постоянное место: `AgentPulse.exe`, `pulse-collector.exe` и `pulse-runtime` должны оставаться вместе. Системный Python для приложения не нужен. |
| Linux | Готового GUI-пакета нет | Только collector/локальный MCP из исходников: Python 3.11+ и отдельное venv; [инструкция headless](HEADLESS.ru.md). Доступность адаптеров зависит от клиента. |
| Windows ARM64, иные ОС/архитектуры | Отдельного проверенного пакета нет | Не обещайте нативную поддержку или проверенную эмуляцию. Сначала выясните совместимость; не устанавливайте другой пакет наугад. |

Скачайте пакет нужной архитектуры из [релизов](https://github.com/Lobodagram/agent-pulse/releases/latest), сверьте SHA256 с `SHA256SUMS.txt` и прочтите ограничения выбранной версии. Сумма проверяет совпадение с манифестом, а не заменяет подпись. Не копируйте исходные/сборочные команды Mac в PowerShell.

Готовый MCP не требует отдельного Python: на Mac команда — абсолютный путь к `Agent Pulse.app/Contents/Resources/pulse-collector`, на Windows — абсолютный путь к распакованному `pulse-collector.exe`; аргументы — `["mcp"]`. Передавайте путь отдельным полем команды в конфиге клиента, сохраняя пробелы; не используйте GUI `AgentPulse.exe` как stdio-сервер. Дополнительное управление включается отдельно по запросу владельца.

Для запуска **из исходников** на Mac/Linux создайте venv через `python3 -m venv .venv`, затем `.venv/bin/python -m pip install .`; на Windows — `py -3.12 -m venv .venv` (или проверенный Python 3.11+), затем `.venv\Scripts\python.exe -m pip install .`. Для исходного Windows-виджета проверьте Tk (`python -c "import tkinter"`) в выбранной среде. Runtime collector использует стандартную библиотеку. Только **сборка приложения** требует Xcode Command Line Tools на Mac и pinned PyInstaller в отдельном build-venv; [команды для каждой ОС](BUILDING.md).

Установщик переносимых навыков ниже требует Python 3.11+ и исходники; это необязательный отдельный шаг. Если пользователь хочет только готовое приложение/MCP, не ставьте ради него Python: агент может прочитать `agent-skills/*/SKILL.md` непосредственно из проверенных исходников.

Основные проверки аналитики общие для платформ, но меню macOS и трей Windows различаются. Зелёный CI не заменяет физическую Windows-приёмку DPI/трея/sleep-wake; готовая установка не доказывает сбор событий. Итог настройки: версия/путь/ОС/архитектура, выбранные клиенты, доступные MCP-инструменты и реальные последующие события, плюс непроверенные функции. Собственные ключи пользователь вводит локально; не копируйте чужие конфиги или учётные данные.

## Два переносимых навыка

Скачайте проверенные исходники релиза. Из этой папки выполните Python 3.11+:

```sh
python scripts/install_agent_skills.py --destination ~/.agents/skills
```

Codex обнаруживает навыки в этой пользовательской папке. Для ZCode укажите `~/.zcode/skills`; для другого клиента — его документированную папку или предложите прочитать SKILL.md вручную. Установщик сохраняет существующие навыки, отказывается перезаписывать совпадающие имена и переходить по симлинкам. Он не меняет конфиги MCP и не запускает агента. Навыки выбираются по задаче; перечитайте их штатным способом клиента.

## CLI и локальный MCP

В отдельном venv команда `python -m pip install .` устанавливает `agent-pulse` и `agent-pulse-mcp`. Можно пользоваться `python collector.py` из исходников или упакованным `pulse-collector`: на Mac внутри приложения Contents/Resources, на Windows рядом с AgentPulse.exe. В конфигурациях клиентов используйте абсолютные пути.

```sh
agent-pulse catalog
agent-pulse settings
agent-pulse journal --format markdown --language ru
codex mcp add agent-pulse -- agent-pulse-mcp
```

По умолчанию доступны только чтения: pulse_report, pulse_session, pulse_evidence, pulse_compare, pulse_review_pack, pulse_settings, pulse_efficiency, pulse_compare_tasks. В ZCode добавьте STDIO-сервер через настройки MCP: команда — абсолютный путь к agent-pulse-mcp, аргументы — пустой массив. Его родной конфиг использует mcp.servers. Формат `.agents/mcp.json` с mcpServers — запасной; при наличии родных серверов того же уровня он пропускается. Сохраняйте прежние подключения. Claude, Kimi и другие MCP-клиенты могут подключить тот же STDIO-процесс через свои штатные настройки; подтверждайте реальный список инструментов.

## Управление по выбору

При явном запросе владельца используйте `agent-pulse-mcp --allow-control`, для упакованного обработчика — `pulse-collector mcp --allow-control`. Четыре дополнительных инструмента меняют ограниченные настройки, ручные даты подписок, решения по находкам и метки сессий. Они не принимают ключи, пути экспорта, произвольные команды и не устанавливают хуки.

pulse_configure принимает changes. Поля: enabledProviders, localPatterns, localTokens, language (en/ru), widgetScale (0.8–1), displayMode (floating/menu/compact/tray), metricMode (limits/today), topmost, menuNumbers, menuFollowActive. На Mac compact/tray означают строку меню; Windows преобразует menu в tray. Флаги меню относятся к macOS. Изменения внешнего вида проверяются примерно каждые пять секунд; показатели клиентов обновляются по обычному расписанию или вручную.

```sh
printf '%s' '{"enabledProviders":["codex","glm"],"metricMode":"limits","widgetScale":0.8}' | agent-pulse settings --update
agent-pulse settings
```

Дату оплаты указывайте со слов владельца; сброс квоты — другая дата. Личные ключи GLM и Kimi Code вводятся в защищённые поля приложения; ключи других адаптеров — по их локальной инструкции. Не передавайте их в чат или аргументы команды. pulse_settings исключает неизвестные поля конфига и ключи; диагностика ошибок использует фиксированные категории.

## Сбор и полезность

Наблюдатель подключается отдельно и по запросу: `agent-pulse hooks --provider codex --action install`, также glm/claude и kimi для Kimi Code 2.x. Обратное действие — remove. Чужие хуки сохраняются; штатное доверие клиента нельзя обходить. MCP не меняет эти настройки и не запускает сессии.

Проверяйте реальные последующие вызовы, пары событий, пропуски и неизвестные исходы. Ноль находок может означать недостигнутый порог; отсутствующие показатели не равны нулю. Тестовые события держите в отдельном `--state`. Прежде чем отметить находку выполненной или задачу принятой, требуется реальное изменение и проверенный результат. Следуйте [циклу улучшения](IMPROVEMENT_LOOP.ru.md). Ручные настройки и аналитика доступны без навыков/MCP.

Проверено 07.10.2026: [Codex навыки](https://developers.openai.com/codex/skills), [Codex MCP](https://developers.openai.com/codex/mcp), [ZCode навыки](https://zcode.z.ai/en/docs/skill), [ZCode MCP](https://zcode.z.ai/en/docs/mcp-services). Поддержка каждым сторонним клиентом зависит от его версии; универсальная сертификация не заявляется.

## Одновременная настройка

Встроенные UI, CLI и MCP записывают только изменённые поля под общей межпроцессной блокировкой, атомарно заменяют файл и увеличивают `configRevision`. Номер возвращается при чтении и успешной настройке. Разные поля сохраняются вместе; для одного поля побеждает последняя завершённая запись. Диалога конфликтов и гарантии compare-and-swap нет. Открытый выбор клиентов — черновик: «Применить» заменяет всю эту группу. При занятом файле запись прекращается через секунду без изменения конфига; повторите после завершения другой операции. Не редактируйте config.json напрямую во время работы приложения.

Mac и Windows проверяют визуальные настройки примерно каждые пять секунд; снапшоты и состав клиентов обновляются отдельно. Все открытые формы мгновенно не синхронизируются. `pulse_settings` не создаёт отсутствующую папку или базу, не инициализирует схему и не выполняет миграции.

`pulse_settings.config` показывает записанные поля, а не все действующие значения интерфейса. Старые визуальные настройки Mac могут оставаться в UserDefaults, если их нет в конфиге. Отсутствие поля не доказывает его значение; явно настройте запрошенный параметр или проверьте интерфейс приложения владельца.

## Какой именно Kimi

Сначала определите клиент и версию. Наблюдатель предназначен для TypeScript Kimi Code 2.x: глобальный `~/.kimi-code/config.toml` (либо `KIMI_CODE_HOME`). Чужие настройки сохраняются; удаляется только помеченный блок. Не устанавливайте его в старый Python `~/.kimi/config.toml`. Необязательный личный ключ Kimi Code вводится в защищённое поле Agent Pulse и хранится только в локальном Secrets.json. Вход в Kimi Work/Chat его не заменяет. Квоты измеряются в единицах провайдера, а не в дневных токенах. События показывают действия, но не обещают токены каждого вызова или код выхода Shell. Установка, тестовые данные и наличие подписки не доказывают живой сбор аккаунта. См. [покрытие Kimi](PROVIDERS.ru.md#kimi-code).

## Автозапуск

В настройках включите **«Запускать при входе в систему»**. При открытии программы автозапуск сам не включается. На macOS приложение должно находиться в «Программах»; используется штатный [SMAppService](https://developer.apple.com/documentation/servicemanagement/smappservice/mainapp). Если нужно одобрение macOS, показаны состояние ожидания и кнопка перехода к объектам входа. Снятие галочки отменяет автозапуск, не закрывая текущее окно. Изменения в системных настройках перечитываются при возвращении в приложение.

На Windows меняется только запись `AgentPulse` текущего пользователя в [Run](https://learn.microsoft.com/en-us/windows/win32/setupapi/run-and-runonce-registry-keys). Другие программы сохраняются. Готовая сборка регистрирует свой exe; режим исходников — интерпретатор и скрипт без тестовых аргументов. Windows может отдельно заблокировать запуск в параметрах автозагрузки. Демо не меняет автозапуск; настоящая перезагрузка/повторный вход проверяются отдельно.
