# Диагностика ошибок и свежесть реестра

Версия 0.14.6 добавляет `resultEvidence` по всей выбранной совокупности вызовов клиента: отсутствующие завершения, завершённые вызовы с неизвестным исходом, основания результата и инструменты с неизвестными исходами. Новые завершения получают `responseEnvelope` в боковой таблице `response_envelope`: фиксированные типы JSON-контейнеров, состояния полей кода завершения, ограниченные числа блоков и источник уже существующей категории ошибки. Ключи, вывод команд, сообщения и стеки не сохраняются. Это диагностика, а не новый классификатор: JSON внутри строки, обычный stdout, неподдержанные поля и отсутствующий штатный код остаются неизвестными.

Формат относится к первой полученной доставке завершения. Поздняя повторная доставка может обновить прежний штатный исход, не меняя первичный формат. История и повторные доставки не дополняются задним числом; повреждённые или отсутствующие данные недоступны. `envelopeRecorded` — число завершений с доступной формой, не число известных исходов или полных пар. У незавершённого вызова формы завершения нет. Сводка неизвестных форм включает полученные завершения без начала. Три колонки `call_metadata` и все прежние правила исходов сохранены.

[Официальный контракт PostToolUse Codex](https://learn.chatgpt.com/docs/hooks), проверен 2026-10-16, передаёт специфичный для инструмента JSON и обычно вывод для модели у локальных инструментов. Он не гарантирует отдельное типизированное поле завершения каждого инструмента. Нельзя извлекать выдуманный код из строк или объявлять день безошибочным при отсутствующих исходах. Новые поля отделяют пропуск доставки от отсутствия распознаваемого кода. Исторические штатные ответы не сохранялись и не восстанавливаются.

`commandCoverage` показывает долю записанных shell-вызовов с распознанным типом внешней команды, включая ошибки и незавершённые вызовы. Это отдельный показатель от охвата результатов. В 0.14.2 поддержаны ограниченные переносы строк, простые перенаправления, команды проверок/файлов, префиксы каталога/окружения и один завершающий here-document. Содержимое Python/Node/shell остаётся непрозрачным: `run.python-stdin` означает тип внешнего запуска, а не выполнение тестов или успешную работу кода. Подстановки, неверные перенаправления и неоднозначные блоки остаются неизвестными. Аргументы, пути, код и имена разделителей отбрасываются. Старые неизвестные команды не восстанавливаются.

`skillEvidenceCoverage` разделяет успешные штатные Skill с совпадением в проверенном каталоге, успешные Skill без совпадения и чтения точного файла навыка. Неизвестные имена не сохраняются. Учитываются уже отсканированные идентичности и хэши путей поддерживаемых клиентов: успешное чтение GLM точного файла общего каталога можно зафиксировать под GLM, даже если навыка нет в его профильном реестре. Совпадение только имени папки недостаточно. Настройка MCP другого клиента не переносится. У такого навыка остаётся статус «вне реестра этого клиента». Это относится к будущим событиям: старые пути и пропущенные Skill не восстанавливаются.

Чтение подтверждает только наблюдаемый доступ; успешный Skill — переданный вызов имени, а не версию, применение к задаче или качество. Для применения и сравнения нужны регистрация версии и явная оценка выбранной задачи из [цикла улучшений](IMPROVEMENT_LOOP.ru.md). Отсутствие событий не доказывает неиспользование. Автоматическая разметка задач, приёмки и запуск агентов не добавлены.

Pulse группирует сохранённые безопасные метаданные по клиенту, инструменту и семейству операций. Если в группе есть хотя бы три парных вызова с известной ошибкой, она попадает в диагностику, даже если запросы разные. Это отдельный сигнал для проверки: он не доказывает общую причину ошибок или отсутствие скилла. Старые сообщения об ошибках не сохранялись; восстановить их нельзя.

У будущих ошибок сохраняется только категория из фиксированного списка: например, syntax, reference, type, timeout, permission или module-not-found. Она берётся из известного структурированного имени/кода либо точного заголовка исключения в начале короткого ответа завершившегося с ошибкой инструмента, кроме shell. Текст, аргументы и стек отбрасываются. Противоречия остаются противоречиями, отсутствующая категория — неизвестной. Это сообщённая клиентом категория, а не доказанная причина. Shell-вывод и успешные ответы не дают категорию по заголовку исключения. Отдельная таблица сохраняет совместимость прежних наблюдателей.

Доля ошибок считается только среди парных вызовов с известным штатным результатом. Неизвестные коды завершения, незавершённые вызовы и вызовы без начала исключены из знаменателя. Рядом доступна доля вызовов, для которых результат вообще известен. При отсутствии известных результатов доля ошибок недоступна. Завершение MCP-вызова имеет прежний смысл штатного конверта ответа; правильность бизнес-результата не подтверждается. Усечение групп отмечается явно.

```sh
python collector.py journal --action diagnostics
python collector.py journal --action diagnostics --date 2026-10-10 --utc-offset-minutes 120
```

Выборка за местный день строится по времени начала вызова, а при его отсутствии — по времени завершения. Используются все сохранённые метаданные, а не последние 100 вызовов. Смещение UTC нужно указать для выбранной даты; по умолчанию используется UTC. Срок хранения и неизвестные пропуски наблюдения сохраняют значение. Read-only MCP `pulse_diagnostics` принимает `date` и `utcOffsetMinutes`. Диагностика также добавлена в обычный отчёт и компактную сводку.

Дата сканирования реестра означает обнаружение настроек, а не доступность инструмента или его использование. Прежний срок свежести — семь дней. Даже свежая по этому правилу запись может не учитывать недавно добавленный скилл.

```sh
python collector.py journal --action scan --provider codex --skills-dir /absolute/skills
python collector.py journal --action scan --provider glm --skills-dir /absolute/profile --trusted-skills-dir /absolute/shared-skills
```

По умолчанию ссылки на папки навыков пропускаются. `--trusted-skills-dir` разрешает только ссылки, цель которых — непосредственная папка навыка в явно доверенной общей директории. Ссылки на сам SKILL.md по-прежнему пропускаются. Инструкции при сканировании не читаются. Для разрешённого навыка сохраняются хэши обоих путей — из профиля и общей папки. Чтение инструкции не доказывает понимание или применение.

Флаг `--remember-sources` при успешном сканировании включает обновление этих источников раз в час при обычном обновлении Pulse. Автоматического поиска других клиентов, кэшей плагинов, проектов или сессий нет. Локальный `inventory-sources.json` хранит пути и даты; секреты туда не записываются. Пути не попадают в аналитику, экспорт телеметрии или ответы MCP. Статус найденного инструмента — «настроен», пока его доступность отдельно не проверена.

Если источник пропал или стал некорректным, сохраняется последняя успешная версия реестра клиента; повторная попытка — через час. Записи и привязки другого клиента сохраняются. Запись источников защищена ограниченным по времени локом. Слишком большая выборка завершается явной ошибкой без замены реестра частичным списком. Обновление не запускает инструменты, модели или второй цикл агента. Удаление локального `inventory-sources.json` отключает запомненное обновление; настройки нативных клиентов не меняются.

Диагностика не доказывает экономию токенов. Квитанции помощников учитываются отдельно от штатных исходов и приёмки человеком. Обычный текст shell-вывода не превращается в достоверный код завершения.

## Причины пропусков распознавания и версия сборщика

Начиная с 0.14.5 (входит в 0.14.6), сборщик сохраняет ограниченные метки частей новых shell-событий в отдельной `command_components`. Частично известная цепочка остаётся неизвестной как целый вызов; известные семейства её частей показаны отдельно. Эти метки не устанавливают, какая ветка выполнилась, результат каждой части или назначение задачи. Конвейер и условные операторы — только записанный синтаксис. Содержимое скриптов и неизвестные команды остаются непрозрачными. Простые присваивания переменных и внешние `echo`/`printf` получают фиксированные семейства; взятые в кавычки имена команд, похожие на присваивания, остаются неизвестными. Вызовы только с присваиваниями/выводом исключены из гипотез автоматизации и остаются границами последовательностей; их счётчики и результаты сохраняются. История и повторные доставки не дополняются задним числом.

`commandCoverage.components` показывает охват данных, состояния разбора, число частичных вызовов и известных/неизвестных частей. Части не становятся дополнительными вызовами инструментов. Старые или повреждённые данные недоступны, а не означают ноль по всей работе. Вызов получает `commandComponents` по предпочтительной фазе начала (по завершению, если начало отсутствует); недостающие метаданные начала не заимствуются из более нового завершения. Прежние шаблоны, счётчики и результаты выполнения сохранены. Три колонки `call_metadata` остаются совместимыми со старыми наблюдателями.

Начиная с 0.14.4 для будущих событий инструментов сохраняются публичная версия сборщика и фиксированный код распознавания в отдельной `collection_metadata`. Старый контракт записи трёх колонок `call_metadata` сохранён. Коды различают отсутствие/размер команды, неподдержанный here-doc, подстановку shell, лимит строк/цепочки, неподдержанное перенаправление, незавершённые кавычки, нераспознанный запуск и частично известную цепочку. Это ограничение парсера; код не устанавливает назначение команды, отсутствие программы или причину ошибки. Правила распознавания остаются консервативными.

Сохраняются только фиксированные метки, без команд, кода скриптов, адресов и сообщений исключений. Тело допустимого конечного here-doc удаляется до проверки подстановок: его содержимое не влияет на метку. Прошлые записи и повторная доставка старого события не дополняются выдуманной историей. Для них причина — `not-recorded`.

Вызовы получают `collectorVersion`, `collectorVersions`, `collectorVersionCoverage`. Это версия, впервые обработавшая полученную запись, не версия клиента, инструмента или модели и не точная версия на момент выполнения операции. Охват относится к полученным фазам и не доказывает наличие пары начала/конца. Неполные метаданные остаются partial/unknown, разные версии — mixed. Диагностика и дневной JSON/Markdown показывают количество вызовов по версиям сборщика. При разрешённой исторической проекции версия относится ко времени обработки проекции.

Поля помогают будущим сравнениям охвата. Они не доказывают сопоставимость задач, качество, применение скиллов или экономию подписки. Ненулевые shell-коды остаются техническими неуспешными исходами; причина и допустимость такого результата для задачи требуют отдельной проверки.
