# Локальная аналитика сценариев

[English](ANALYTICS.md)

Цель — собрать доказательства для улучшения песочницы агента и затем проверить эффект изменения. Анализ выполняется на устройстве, без вызовов моделей и отправки телеметрии.

## Подключение

Настройки → Локальные наблюдатели → Включить Codex, GLM/ZCode или Claude. Другие хуки и настройки сохраняются; удаляются только обработчики Agent Pulse. Затем начните **новую сессию клиента**. Codex может попросить проверить доверие локальной команде — установщик этого не обходит и сам агентов не запускает. Сообщение «настроено» не означает «получает события»: после обычной задачи проверьте состояние в «Сценариях» и число пар вызовов. Одно событие запуска сессии не доказывает охват инструментов.

Из исходников, Python 3.11+:

```sh
python3 collector.py hooks --provider codex --action install
python3 collector.py hooks --provider glm --action install
python3 collector.py hooks --provider codex --action remove
python3 collector.py journal --action report
```

В Mac-пакете сборщик находится в `Agent Pulse.app/Contents/Resources/pulse-collector`; в Windows рядом с `AgentPulse.exe` лежит отдельный `pulse-collector.exe`. После подключения не переносите сборщик: путь записан в хуки. После переноса включите наблюдатель заново. Вход ограничен 1 МиБ, таймаут клиента — 2 секунды. Хук ничего не пишет в чат, не принимает решений о правах и не вызывает модель. При сбое пропускает событие и позволяет работе агента продолжиться. Есть небольшие затраты CPU/времени, без отдельного модельного расхода подписки.

## Что выявляется

- Цепочки из 2–4 разных категорий, повторившиеся хотя бы в трёх наблюдаемых ходах. Разные агенты, сессии и проекты разделены. Перекрывающиеся вызовы, ошибки и промежутки больше десяти минут разрывают цепочку. Порядок не доказывает причинность.
- Одинаковые запросы: локальный HMAC входа повторяется от четырёх раз в двух ходах. Сам вход не хранится.
- Повтор ошибок: три неудачных одинаковых запроса. Рекомендация — исправить причину, а не автоматически сделать новый MCP.
- Повтор чтения: три обращения к одному хешированному файлу с прежними размером/mtime в ходе. Метаданные не доказывают неизменность содержимого. Признак доступен только инструментам с явным полем пути; пути из shell не восстанавливаются.
- Семейства операций: десять вызовов в трёх ходах, низкая уверенность. Составные shell-команды сохраняются как `shell <compound>`; внутренние команды не трассируются.

«Сценарии» → «Посмотреть примеры» открывает сессию. Свежий список ограничен; CLI показывает до 500 вызовов сессии, MCP — до 100. Примеры вне свежего списка можно читать по хешу сессии, пока они хранятся. Времена параллельных вызовов не суммируются. Без завершения исход «ожидается», без кода shell-выхода — «неизвестно». Запуск и окончание асинхронного процесса могут быть разными инструментами: все такие процессы пока не связываются автоматически.

Токены провайдеров не равны стоимости конкретной команды. Контракт журнала принимает явные нативные токены хода, но **эти хуки не обещают их живую передачу**. Разница общих счётчиков не приписывается отдельной параллельной задаче. Проценты подписки не переводятся в выдуманные токены.

## Каталог возможностей

Читаются только имена из явно указанных папок и конфигов, без содержимого скиллов:

```sh
python3 collector.py journal --action scan --provider codex --skills-dir /your/skills --config /your/config.toml
```

Можно импортировать JSON-массив с полями `provider`, безопасное `id`, `kind` (skill/tool/mcp), `category` (read/search/edit/test/build/inspect/environment/remote/delegate/shell/other), `status` (configured/available/disabled/unavailable). `available` указывайте только после живой проверки подключения. Сканер устанавливает лишь configured. Каталог устаревает через семь дней; отсутствие совпадения не доказывает, что инструмента вообще нет. Совпадение категории не доказывает заменяемость. Обновление одного провайдера сохраняет дату каталога другого.

## Проверка до/после

В «Сессиях» укажите нечувствительную ASCII-метку задачи, вариант before/after и исход: принято, ошибка, доработка или неизвестно. После изменения одного сценария отметьте новые сессии. Для наблюдательного сравнения нужно хотя бы три сессии на вариант. Показываются медианы числа вызовов/времени и результаты приёмки. Вы сами сверяете сложность задач, модель и её настройки. Непереданные сведения остаются неизвестными. Ошибки и доработки учитываются; причинность и гарантированная экономия не заявляются.

```sh
python3 collector.py journal --action compare --label test-module --before before --after after
python3 collector.py journal --action export --file /your/private/report.json
```

Экспорт даже без текстов содержит личные сведения о работе. Он не отправляется и не публикуется автоматически; проверьте его перед передачей.

## Локальный MCP

Команда `python3 /absolute/checkout/collector.py mcp`, либо установленный `pulse-collector` с аргументом `mcp`. В клиенте MCP укажите абсолютный путь к исполняемому файлу. Для исходников аргументы включают абсолютный путь `collector.py` перед `mcp`. Для другой папки журнала глобальные `--state /your/state` ставятся перед `mcp`. Ключ/порт не нужны. Инструменты: `pulse_report`, `pulse_session`, `pulse_compare`; без запуска команд, управления клиентом, установки скиллов и агентского цикла. Чтение может обслуживать собственный кеш. Регистрация добровольная, автоматически не выполняется.

## Охват и хранение

Наблюдаются только доставленные события. Hosted-инструменты, внутренние рассуждения, отключённые хуки, спящий компьютер и клиенты без хуков могут отсутствовать. Импорт агрегатов и прежний ограниченный анализ счётчиков Codex отделены от нового журнала — они не создают трассу каждого шага. Полнота охвата неизвестна.

Собственная SQLite-база хранится локально. Идентификаторы сессий, проектов, ресурсов и входов — HMAC с локальным ключом в Secrets.json: это псевдонимы, не гарантия публичной анонимности. Не сохраняются промпты, аргументы, результаты, код, пароли, транскрипты и абсолютные пути проектов. Сохраняются фиксированные безопасные формы команд и очищенные имена инструментов/моделей. Очистка — 30 дней, до 100 000 событий; проверка каждые 500 событий и при отчёте. Анализ ограничен последними 20 000 событиями. Основная база ограничена 256 МиБ; при переполнении/блокировке событие может пропасть. Резервируйте состояние вместе с Secrets.json: смена ключа нарушает сопоставление. Нативные базы разговоров не читаются и не меняются.

Рабочий цикл: проверить примеры → выбрать существующий инструмент или сделать проверенный скрипт/скилл/MCP → сравнить сходные задачи → проверить качество и расход. Agent Pulse даёт доказательства, но самовольно песочницу не переписывает.


Смена аккаунта: каждые пять секунд проверяются только метаданные файлов входа/конфигурации выбранных поддерживаемых клиентов, без чтения секретов. Изменение убирает прежние значения и запрашивает свежие. Codex дополнительно проверяет штатный идентификатор аккаунта, сохраняя лишь локальный HMAC: текущие квоты аккаунтов не смешиваются, прежняя ручная дата оплаты очищается при подтверждённой смене. При неизвестном аккаунте/ошибке прежние квоты не подставляются; запоздавшие ответы отбрасываются. Это поддерживаемые сигналы, не универсальное мгновенное определение аккаунтов всех IDE: вход только через Keychain или неподдерживаемый клиент может требовать минутного опроса/ручного обновления. Статистика ZCode — локальная история клиента, не автоматически разделённая платная статистика аккаунтов.


Общая история работы остаётся непрерывной при смене аккаунтов. Журнал объединяется по провайдеру/задаче, без разделения по логинам. Дневные отчёты Codex сохраняются по хешу аккаунта и дню, обновляются без повторного прибавления и затем суммируются. Возврат в старый аккаунт не удваивает его расход. Прежние записи без установленного аккаунта сохраняются, но не прибавляются к пересекающемуся известному дню: иначе нельзя исключить двойной счёт. Общий расход охватывает наблюдаемые аккаунты, не обещает учёт всех когда-либо использованных. Текущие квоты/даты оплаты остаются отдельно; GLM сохраняет локальную историю клиента.
