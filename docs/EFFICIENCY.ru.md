# Польза скиллов, MCP и инструментов

[English](EFFICIENCY.md)

В 0.11.0 Pulse связывает находку → публичное имя и версию навыка → выбранные вызовы задачи → её приёмку. Всё хранится локально. Модели и платные оценщики не вызываются.

1. В «Навыках» добавьте версию скилла, MCP или инструмента для нужного клиента. Находка необязательна. Версия неизменна: для нового поведения зарегистрируйте новую версию. Используйте публичные ASCII-метки без секретов и названий клиентов.
2. В «Сессиях» выберите первый и последний вызовы задачи на текущей странице, метку семейства задач, вариант (`before` / `after`), версию критерия приёмки и настоящий результат (`accepted`, `failed`, `rework`, `unknown`). При необходимости выберите основную версию навыка и подтвердите её применение. Галочка — ваша отметка, а не доказательство штатного вызова версии.
3. Карточка в «Навыках» покажет приёмку, известные исходы инструментов и охват расхода. В «Сравнении» выберите одного клиента и одинаковую метку семейства задач. Старый режим сравнения сессий сохранён.

Выборка должна быть последовательной в наблюдениях одного исполнителя, сессии и проекта. Пересечения запрещены. Повторная оценка той же выборки с теми же метками меняет результат и отметку применения, не создавая копию. Одна задача связывается с одной основной версией: независимую экономию совместно применённых навыков Pulse не распределяет. Граница страницы ограничивает выборку; длинную задачу нельзя искусственно делить ради лучшей метрики.

| Показатель | Расчёт и пределы |
| --- | --- |
| Приёмка | Принятые / проверенные задачи; `unknown` отдельно от отказа. Ручная оценка по указанному критерию. |
| Токены / результат | Вход + выход всех выбранных попыток, включая ошибки, доработки и непроверенные попытки, / число принятых результатов. Только при полном переданном расходе всех задач группы. |
| Вход из кэша | Cached input / input. Cached input уже входит во вход, второй раз не прибавляется. Доля кэша не равна экономии подписки. |
| Вызовы модели | Только явный переданный счётчик. Не число вызовов инструментов или ходов. |
| Медиана времени | От первого старта до последнего завершения задачи. Включает ожидания, не означает активное время модели; рядом число задач с доступным временем. |
| Применение | Наблюдаемые вызовы имени и ручные отметки версии отдельно. Чтение SKILL.md не доказывает применение. |

Для расхода вся наблюдаемая часть каждого хода должна принадлежать задаче, а вызовы иметь начало и конец. Разделённый ход, поздний вызов, неизвестная граница хода, лимит событий, несовпадающие источники или неполные счётчики блокируют показатель. Полноту счётчика заявляет передающая сторона, независимой проверки нет. Невидимая активность остаётся ограничением.

Процент изменения токенов появляется после минимум трёх задач в каждом варианте, с одинаковым наблюдаемым составом проектов/моделей/критериев, полной приёмкой и расходом, без падения доли приёмки. Это минимальный порог интерфейса, не статистическая значимость. Проверяйте сложность задач, настройки reasoning, скрытые расходы и параллельную работу. Разница наблюдений не доказывает вклад навыка. Целевой процент внедрения неизвестен без числа подходящих задач.

**Лимиты подписки отдельно.** Pulse не переводит проценты пятичасового окна или кредиты в токены. Текущие хуки не гарантируют токены хода, поэтому в настоящих карточках сначала может быть `—`. Не заполняйте его оценками.

Версия 0.11.1 добавляет **локальную детализацию дня** в «Обзор» и `pulse_efficiency.localTokenProfile`. Используется уже включаемый пользователем сбор токенов: вход, выход, кэшированный вход, доля кэша во входе и охват детализации среди наблюдаемых токенов. Даже 100% детализации не означает полный охват аккаунта или задачи. Дневной счётчик аккаунта не используется как знаменатель. При выключенном сборе или Codex профиль не выдаётся через MCP; MCP читает сохранённые значения без запуска нативного сбора.

Разности проверенных счётчиков используются только при непрерывной базе внутри одного дня UTC. Первая запись, пропуск схемы и переход дня учитывают лишь проверенный последний запрос в пределах наблюдаемого прироста. Сбросы, противоречивые разности кэша и неизвестные поля не создают отрицательные значения или полные квитанции задач. Повторы не суммируются; старые значения остаются без детализации, история разговоров заново не читается. Кэш уже входит во вход, reasoning — в выход. Число запросов модели, польза навыка и экономия подписки не выводятся. [Формат transcript нестабилен](https://learn.chatgpt.com/docs/hooks), неподдерживаемая детализация остаётся неизвестной. Контракт проверен на Codex CLI 0.160.0 от 2026-10-09: [события расхода](https://learn.chatgpt.com/docs/app-server) относятся к активному чату, а ответы метаданных ходов установленной версии не содержат полного расхода.

Метаданные версии/задачи передаются JSON через `journal --action asset|task --file metadata.json` (до 64 КиБ). Для задачи нужны `provider`, эфемерная `taskId`, `label`, `variant`, `criterion`, `outcome`, `callIds`; необязательны `assetId`, `version`, `applied`. Исходная taskId не сохраняется, только HMAC. Для повторной оценки используйте тот же исходный идентификатор. В интерфейсе он формируется из границ выборки. Хешированные id вызовов возьмите из `pulse_session`, а не из номеров на экране.

```sh
python collector.py journal --action asset --metadata '{"provider":"codex","assetId":"release-helper","version":"1.0.0","kind":"skill"}'
python collector.py journal --action compare-tasks --provider codex --label release-check --before before --after after
```

Только если клиент действительно предоставляет счётчики, `journal --action usage --file receipt.json` принимает `provider`, нативные `sessionId` / `turnId`, целые неотрицательные `input`, `cached_input`, `output`, необязательные `modelRequests`, `complete` (по умолчанию false). Идентификаторы немедленно хешируются. Текст, произвольный `source` и оценочные значения не принимаются. `complete: true` — заявление источника. Извлечения счётчиков из произвольного вывода или баз разговоров нет.

MCP по умолчанию добавляет только чтение: `pulse_efficiency`, `pulse_compare_tasks`. Явный `--allow-control` также включает `pulse_register_asset`, `pulse_record_task`, `pulse_record_usage`. Это собственные локальные записи Pulse, без изменения нативных hooks, разрешений или модели. Превью MCP ограничены, усечение отмечено; полный ограниченный отчёт доступен локально через CLI.

Задачи/расход и связи с вызовами живут в прежнем 30-дневном окне, максимум 1000 задач и 200 версий. Публичный каталог версий сохраняется до очистки своего состояния. Старые записи без признака полноты не становятся полными после обновления.

Первый пилот: реальные проверки релиза; второй: реальные проверки экспорта 3D. Сохраните одинаковый критерий качества, соберите обе группы и отмечайте неудачные попытки. Синтетические тесты доказывают работу расчётов, но не экономию вашей работы.
