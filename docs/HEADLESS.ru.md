# Linux и работа без виджета

На Linux поддерживаются Python 3.11+ сборщик/журнал и локальный stdio MCP без графического виджета. Это режим исполнения, а не установщик рабочего стола Linux. Графические пакеты macOS/Windows выпускаются отдельно.

В проверенной копии исходников:

```sh
python3 -m venv .venv
. .venv/bin/activate
python -m pip install .
agent-pulse journal
agent-pulse journal --format markdown --language ru
agent-pulse-mcp
```

`agent-pulse-mcp` ждёт JSON-RPC во stdin; это не сетевой сервер. Подключение задаётся явно в настройках MCP выбранного клиента. Чтение собственного журнала не вызывает модели и не запускает агентские клиенты. До появления событий из поддерживаемых добровольных хуков/импортов журнал будет пустым. Выбор провайдера сам по себе не включает трассировку команд и не открывает данные оплаты. См. [покрытие клиентов](PROVIDERS.ru.md), [установку/удаление наблюдателя](ANALYTICS.ru.md) и [чтение аналитики](READING_ANALYTICS.ru.md).

В wheel входят обработчик хуков и две команды CLI, без скриптов тестирования/рендеринга. Из исходников, при установленных setuptools 68+ и wheel, `python scripts/package_smoke.py` проверяет сборку/установку и вымышленные события в изолированном окружении. Инструменты разработки остаются в исходниках. Версия метаданных берётся из `pulse_version.__version__`; её используют MCP и проверки сборок по [контракту setuptools](https://setuptools.pypa.io/en/latest/userguide/pyproject_config.html#dynamic-metadata).

Графический Linux-клиент, полный сбор всех систем и измеренная экономия подписки не заявляются. Проверки Linux в CI не заменяют подпись macOS, физическую приёмку Windows/DPI и проверку настоящих агентских клиентов.
