# Аудит готовности аналитики · 2026-10-06

[English](AUDIT.md)

Основная цель — доказательства для улучшения песочниц агентов. Для готовности нужны реальный сбор событий, полезные выводы и проверка эффекта изменений. Сейчас это **предварительный продукт; полная непрерывная аналитика работы агентов ещё не подтверждена**.

## Исправления 0.4.1

- Сборщик в режиме одного файла запускался на Mac 6–7 секунд при тайм-ауте хука 2 секунды. Упаковка теперь содержит отдельную папку среды, без распаковки при каждом событии. Тест упакованного наблюдателя ограничен реальными 2 секундами вместо 20. Доверие клиента и новая сессия всё равно необходимы.
- Явная ошибка инструмента вместе с кодом завершения 0 ошибочно считалась успехом. Ошибка теперь имеет приоритет.
- Удаление сбоев перед анализом склеивало цепочки через неуспешные вызовы. Сбои и незавершённые вызовы теперь разрывают цепочку.
- Завершение раньше начала могло участвовать в сценарии. Некорректная хронология теперь разрывает цепочку.
- Непереданная составляющая токенов могла становиться нулём. Теперь она остаётся неизвестной.
- Разные источники одного хода могли удваивать токены. Совпадающие значения учитываются один раз, конфликтующие составляющие остаются неизвестными.
- Одни события жизненного цикла не отображаются как поступление вызовов инструментов.
- Обновлены инструкции сборки/трея, порядок версий и описание основной цели на обоих языках.

## Проверка

83 тест проверяет пары вызовов, сбои, последовательность/параллельность, независимость агентов, неизвестные значения, перечень возможностей, хранение, приватность, обратимость настроек и историю аккаунтов. Тестовые события проходят хук → журнал → отчёт → локальный MCP без вызова модели. Это не доказывает передачу событий из работающего клиента.

Реальная приёмка: включить наблюдатель, открыть новую сессию, подтвердить доверие, если клиент попросит, выполнить обычную задачу чтения/правки/проверки и увидеть поступление вызовов, их пары и примеры. Для повторяющегося сценария нужно минимум три наблюдаемых хода с похожей работой. Тестовые события в настоящий журнал для этой проверки добавлять нельзя.

Штатные счётчики Codex/ZCode проверены на macOS, но они независимы от журнала сценариев. Проверки Windows в CI не заменяют проверку DPI и реальных клиентов на устройстве. Подробности: [QA](QA.md), [поддержка клиентов](PROVIDERS.ru.md).

## Что ещё требуется для основной цели

| Направление | Уже есть | Чего пока нет |
| --- | --- | --- |
| Постоянный сбор | Локальный механизм и проверка тайм-аута | Подтверждённая передача реальных пар от каждого клиента |
| Повторяющаяся работа | Цепочки категорий, одинаковые запросы, сбои/чтения | Репрезентативные задачи и оценка ложных/пропущенных находок |
| Похожие команды | Безопасные формы команд и семейства операций | Составные команды обобщаются; смысловой анализ кода отсутствует |
| Использование скиллов | Вызовы инструментов и явный перечень | Чтение скилла не доказывает применение; универсальная атрибуция использования/неиспользования не реализована |
| Недостающий MCP/скилл | Кандидаты по категориям с примерами | Неполный перечень не доказывает отсутствие инструмента; нужна проверка доступности |
| Эффект улучшений | Ручные метки качества и сравнение вариантов | Сопоставимые задачи, приёмка результата; экономия автоматически не доказана |
| Все клиенты | Нативные хуки для трёх клиентов; счётчики/импорт для остальных | Выбор клиента не создаёт хронологию всех его действий |

## Оценка

**6/10 относительно цели глубокой аналитики.** Сбор: 4/10; алгоритмы: 7/10; атрибуция возможностей: 4/10; проверка качества/эффекта: 5/10; приватность и ограничения ресурсов: 8/10; упаковка/документация: 8/10. Это инженерная оценка, не результат бенчмарка или сертификация безопасности. Исправления не заменяют реальную приёмку.

Приоритет: подтвердить реальный сбор → накопить и проверить повторяющиеся задачи → добавить явные доказательства использования скиллов и актуальность перечня → измерить точность находок → автоматизировать подтверждённый сценарий и сравнить качество/объём работы. Новая модельная петля или векторная база для первого шага не нужны.

Проверенные контракты: [OpenAI hooks](https://learn.chatgpt.com/docs/hooks) описывает доверие и исключения охвата; [ZCode hooks](https://zcode.z.ai/en/docs/hooks) — конфигурацию пользователя и её снимок при старте сессии. Agent Pulse не обходит доверие и не запускает агента самостоятельно.
