# Проверить → внедрить → наблюдать

В Agent Pulse 0.7.0 можно вручную отметить решение по находке: `open` (в работе), `actioned` (внедрено), `dismissed` (отклонено). Отметка хранится только в собственном локальном журнале. В разделе «Сценарии» выберите внедрённый скрипт, скилл или MCP; для CLI:

```sh
python collector.py journal --action review --finding <finding-id> --status actioned --reason skill --days 1
python collector.py journal --format markdown --language ru
python collector.py journal --action export --format markdown --language ru --file review.md
```

Сравниваются равные окна 1/3/7 дней одного провайдера и хешированного проекта. В интерфейсе — 24 часа. Перепроверка ждёт окончания окна; если в любом окне меньше трёх известных ходов, подтверждений недостаточно. Если находка перестала достигать порога, число повторов неизвестно: это не ноль и не доказательство устранения. Равное время не гарантирует одинаковые задачи, сложность, модели или причинную связь. Экономия токенов и подписки не вычисляется. В отчёте до 30 решений, в базе до 200, срок хранения 30 дней. Вернуть или отклонить исчезнувшую находку можно в CLI. В 0.7.0 идентификатор учитывает тип находки; используйте свежий отчёт вместо старых экспортированных ID.

У локального MCP появился инструмент чтения `pulse_review_pack`, параметр `language: en|ru`. Он выдаёт ограниченный Markdown-отчёт для человека, не меняет решения, не выполняет код и не запускает клиентов. Аргументы, результаты, сообщения и секреты не сохраняются. Экспорт остаётся на устройстве; перед передачей его проверяют.

## Общая команда проверки

```sh
python scripts/workflow_check.py check --output work/check.json
python scripts/workflow_check.py handoff --input work/check.json --output work/handoff.json
# Необязательно: скачанные архивы релиза и SHA256SUMS.txt:
python scripts/workflow_check.py check --archives work/downloads --output work/check.json
```

Одна команда объединяет публичный экспорт с проверкой приватности, синтаксис Python, ссылки документации и тесты. Пакет содержит коммит, признак незакоммиченных изменений и хеш публичного дерева исходников, не вывод команд или учётные данные. Передача проверяет типы метаданных и отбрасывает лишние поля. Архивы проверяются по хешам, путям, runtime, уведомлениям и версии Mac; бинарники не запускаются, версия Windows этой проверкой не подтверждается. Интерфейс, сроки хуков, подписи, CI и установленная программа проверяются отдельно. Готовый пакет повторно используют только для того же дерева исходников и применимых проверок; после изменения или ошибки проверяют заново, не по таймеру.

## Учёт применения

Успешный явный Read и строгие буквальные команды `cat`, `sed -n N[,M]p`, `head`, `tail` сопоставляются только с зарегистрированным путём скилла. Анализатор не выполняет команды, не раскрывает переменные, не читает содержимое и не воспроизводит прошлые вызовы. Динамические команды, конвейеры, подстановки и смешанные цепочки остаются неизвестными. Чтение может быть частичным или пустым; оно не доказывает понимание или применение. Вызов Skill и ручная отметка учитываются отдельно. Старые пропуски восстановить невозможно: аргументы уже удалены. Источники чтения различаются в счётчиках.

Пространства MCP видны по именам полученных инструментов, включая незарегистрированные. Это не подтверждение плагина, доступности сервера или замены другой операции. Общие категории каталога `shell`/`other` больше не создают произвольные рекомендации замены.

## Проверка результата

Для повторяемой задачи сохраните одинаковую метку и критерий приёмки качества; запишите варианты before/after в «Сессиях» и сравните достаточно реальных принятых работ. Проверьте различия моделей, пропуски сбора, неизвестные результаты и команды. Новый общий скилл или скрипт остаётся гипотезой, пока реальные задачи не показывают меньше ручных повторов с сопоставимым качеством. Фикстуры проверяют механику; они не попадают в рабочий журнал. Общие файлы связывают клиентов, другой агент автоматически не запускается.
